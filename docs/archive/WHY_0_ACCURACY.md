# 왜 못 풀어? (0% 정확도 원인 정리)

**요약:** 답을 **"추론/실행 출력에서 마지막으로 나온 숫자"**로 고르는 fallback이 있어서, 실제 정답이 아니라 **32** 같은 숫자가 반복해서 선택되고 있음. 그 위에 모델이 `<ANS>`에 진짜 답을 안 넣고, 생성 코드도 틀리는 경우가 많음.

---

## 1. 현재 답이 정해지는 경로 (Path A: Simulator)

1. **코드 생성** → 실행 → `result` = 실행 stdout  
2. **실행에서 추출:** `cleaned_result = extract_final_answer_from_output(result)`  
   - 출력 **마지막 줄**만 보고, 그 줄에서 **첫 숫자**를 답으로 씀.  
3. **추론에서 추출:** `extracted = extract_answer(self.solver.last_reasoning)`  
   - `<ANS>...</ANS>` → 그 안의 값  
   - 없으면 `\boxed{...}`  
   - 없으면 **"answer is X"** 형태  
   - 없으면 **마지막에 숫자만 있는 줄**  
   - 그것도 없으면 **추론 전체 텍스트에서 나온 숫자들 중 마지막 숫자**  
4. **최종 답:** `answer = extracted or cleaned_result`  
   - 추론에서 뽑은 값이 있으면 그걸 쓰고, 없으면 실행 결과에서 뽑은 값 사용.

---

## 2. 5문항 모두 "32"가 나온 이유

- **추론 fallback:**  
  `extract_answer`가 `<ANS>`/`\boxed{}`를 못 찾으면,  
  **"추론 텍스트에 등장한 모든 숫자 중 마지막 것"**을 씀.  
  수식/중간 계산에 32가 한 번만 나와도 (예: 2^5=32, 어떤 길이 32 등), 그게 **맨 뒤**에 있으면 32가 선택됨.
- **실행 fallback:**  
  생성된 코드가 **마지막에 32를 출력**하면 (틀린 식, 중간값, 디버그 등),  
  `extract_final_answer_from_output`가 그걸 그대로 "답"으로 씀.
- **모델이 <ANS>를 제대로 안 채움:**  
  프롬프트에 "Final answer ONLY (compact canonical form)"이라고만 넣고,  
  모델이 실제 답 대신 그 문구만 넣거나 비우면, 우리가 플레이스홀더로 **거부**하고  
  위의 "마지막 숫자" fallback으로 가서 32가 나올 수 있음.

그래서 **문제마다 정답은 다 다른데**, 파이프라인은 **항상 같은 방식으로 "마지막 숫자"를 골라** 32가 반복된 것.

---

## 3. 못 푸는 이유 정리

| 원인 | 설명 |
|------|------|
| **답 추출 fallback이 과함** | 추론/실행 **전체**에서 "마지막 숫자"를 쓰다 보니, 중간값·무관한 숫자(32 등)가 답으로 선택됨. |
| **모델이 <ANS>를 안 채움** | "ONLY compact canonical form."만 넣거나 비우면, 우리가 거부하고 fallback만 쓰게 됨. |
| **생성 코드 품질** | Path A는 코드 생성 후 실행인데, 코드가 틀리거나 중간값만 출력하면 실행 결과도 틀린 값(32 등). |
| **실행 결과 추출 방식** | 출력 **마지막 줄의 숫자 하나**만 쓰다 보니, 여러 줄 중 정답이 아닌 줄이 "답"으로 선택될 수 있음. |

---

## 4. 32가 나온 실제 원인 (확인됨)

- **생성된 "코드"**가 실제 코드가 아니라 **모델 로드 실패 시** 반환되는 **에러 메시지를 print하는 코드**였음.
- 그 코드 실행 시 `print('ERROR: ... 32-bit ...')` 가 출력되고, `extract_final_answer_from_output`가 그 문자열에서 **마지막 숫자 32**를 추출함.
- **조치:** (1) solver: 모델 실패 시 `print('ERROR: Model load failed')` 처럼 **짧은 메시지만** 반환. (2) reasoning_utils: 실행 결과에 `ERROR`/`MODEL FAILED`/`32-BIT`가 있으면 **숫자 추출하지 않고** 출력 그대로 반환.

---

## 5. 적용한 개선 (2026-02-23)

| 항목 | 변경 |
|------|------|
| **extract_answer** | 추론이 **400자 초과**일 때는 "마지막 숫자" fallback을 쓰지 않고 **None** 반환 → 실행 결과(cleaned_result) 사용. |
| **extract_final_answer_from_output** | **Answer:, 결과:, 최종 답안:** 등 **라벨이 붙은 줄**을 우선 사용하고, 없을 때만 마지막 줄 사용. |
| **orchestrator** | 실행 결과가 유효(ERROR 아님)하면 **cleaned_result를 우선** 사용하고, 그 다음 extracted. |
| **solver** | 모델 로드 실패 시 반환하는 "코드"를 **짧은 메시지**로 변경해, 실행 결과에서 32가 추출되지 않도록 함. |
| **extract_final_answer_from_output** | 출력에 ERROR/MODEL FAILED/32-BIT가 있으면 **숫자 추출 생략**, 출력 그대로 반환. |

## 6. 추가 개선 방향 (참고)

1. **프롬프트/모델:**  
   `<ANS>` 안에 **반드시 한 줄로 최종 수치/수식만** 넣도록 강하게 유도 (예시, few-shot).
2. **코드 생성 품질:**  
   생성 코드가 **최종 답만 print**하도록 프롬프트/후처리 강화, 실행 전 간단 검증(문법/의심 패턴) 추가.

위를 반영하면 "32만 나오는" 현상은 줄고, 실제 정답과 맞는 비율(정확도)을 올리는 데 도움이 됨.
