## 1. 현재 수학적 추론 수준 (요약)

### 1.1 벤치마크 수치 (문서 기준)

| 벤치마크 | 현재 수준 | 참고 목표 | 비고 |
|----------|-----------|-----------|------|
| **AIME (90문항)** | **미측정 (TBD)** | 50%+ 경쟁력, 60%+ SOTA | GPT-4 ~45%, 대회 우승 ~58%, 인간 평균 33–40% |
| **NuminaMath 균형 (60문항)** | **미측정** | 전체 55–65% | Easy 80–90%, Medium 60–70%, Hard 30–40% 기대 |
| **검증 모듈 정확도** | 목표 90%+ (P0) | 90%+ | 간단 대수 검증/거부 정확도 |
| **내부 테스트/정규화** | 94% 언급 (일부 문서) | 94%+ 유지 | 특정 서브시스템·커리큘럼 기준으로 추정 |

**정리:**  
- **경쟁/대회 수준의 AIME·Numina 정확도는 아직 공식 실행 결과가 없어 “현재 수준”이 TBD입니다.**  
- 94%는 검증·정규화 등 **일부 컴포넌트/소규모 테스트** 기준으로 보는 것이 맞고, AIME 90문항 전체 정확도와는 별개입니다.

**표 업데이트 방법:** AIME 또는 Numina 평가를 실행한 뒤 `results/`에 저장된 결과와 `results/gradient_report_*.json`을 참고하여, 위 표의 "현재 수준" 칸에 정확도를 채우면 됩니다. 평가 스크립트는 실행 완료 시 자동으로 그라디언트 리포트를 저장합니다.

## 2. 시스템이 갖춘 수학적 추론 “역량” (구현 기준)

아키텍처와 코드 기준으로, **지금 파이프라인이 지원하는 수학적 추론 범위**는 대략 아래와 같습니다.

| 역량 | 구현 여부 | 위치/내용 |
|------|-----------|-----------|
| **도구 통합 추론 (TIR)** | ✅ | CoT + Python 코드 번갈아 생성·실행 (Numina 스타일) |
| **전략 라우팅** | ✅ | Simulator / Theoretician / Hybrid, N 크기·도메인별 선택 (stage3_router) |
| **심볼릭 검증** | ✅ | SymPy (simplify, factor, expand, trigsimp, ratsimp, cancel, nsimplify), 유리수 정규화 (stage5_verification) |
| **수치·집합 비교** | ✅ | 부동소수점 허용오차, Counter 기반 다중집합, 역검증(해 대입) (stage5) |
| **기하 심볼릭** | ✅ | SymPy geometry, 좌표·객체 기반 풀이 (geometric_solver) |
| **도메인별 컨텍스트** | ✅ | Geometry / Number Theory / Algebra 등 프롬프트·라이브러리 주입 (stage2_retrieval) |
| **다단계 추론·재시도** | ✅ | Refine Loop, 검증 실패 시 수정 프롬프트로 재시도 |
| **문제 분해** | ✅ | ProblemDecomposer, 복합 문제 → 서브문제 |
| **증명(proof) 전용 엔진** | ❌ | proof 타입은 분류만 되고, 실제 풀이는 일반 코드/LLM 경로 사용 |

**종합:**  
- **AIME 중하위~중위 수준의 “계산 + 심볼릭 검증”**까지는 인프라가 갖춰져 있음.  
- **IMO 킬러·고난도 증명**은 전용 증명 엔진이 없어, 현재는 “일반 코드 생성 + 검증”에 의존하는 수준으로 보는 것이 맞습니다.

## 3. 수준을 “어디선가”로 보는 방법

- **L1 (기본):** 정확도 하나만 봄 → 이미 넘음 (난이도/소스 분해 있음).  
- **L2 (분층):** 난이도·소스·메서드별 분해 → **현재 여기**.  
- **L3 (통계):** 신뢰구간·McNemar·오류 분류 → advanced_metrics로 **부분 도달**.  
- **L4 (엄밀):** 난이도 구간별 정확도·효과크기·정량적 난이도 → **일부만 연동** (DifficultyMetrics 연동 보강 필요).  
- **L5 (완전):** 도메인별 정확도·리포트 자동화 → **미도달**.

즉, **“평가 체계”의 수학적 완전성**은 **L2~L3 사이**, **“실제 풀이 능력”**은 **AIME/Numina 기준으로는 아직 숫자로 정해지지 않은 상태**라고 보면 됩니다.

## 4. 더 개선하려면 (우선순위)

### 4.1 즉시: 현재 수준을 숫자로 만들기

1. **AIME 90문항 한 번 돌리기**  
   - `examples/run_aime_evaluation.py` (또는 동일 스크립트) 실행.  
   - 결과로 **전체 정확도, 난이도/소스별 정확도** 저장.  
   - 이 한 번이 “현재 수학적 추론 수준”의 기준선이 됨.

2. **NuminaMath 균형 60문항 실행**  
   - Easy/Medium/Hard 비율이 정해진 평가 스크립트 실행.  
   - 난이도별 정확도로 **어디서 막히는지** 파악.

3. **결과를 그라디언트와 연동**  
   - `evaluate_mathematical_and_devops(metrics)` 에 위 결과 넣어서  
     수학 그라디언트(L2/L3/L4) 점수·난이도 그라디언트 트렌드까지 리포트에 포함.

→ **“현재 수준” = 위 두 벤치마크의 정확도 + 난이도별/도메인별 분해**로 정의하는 것이 좋습니다.

### 4.2 단기: 수학적 추론 “품질” 올리기

| 방향 | 내용 |
|------|------|
| **검증 정확도 90%+** | 간단 대수/산술에 대해 SymPy·역검증으로 검증/거부 정확도 측정·개선 (P0 목표 유지). |
| **난이도 점수 연동** | `DifficultyMetrics`(reasoning_steps, concept_count 등)를 평가 스크립트에 넣어, **정량적 난이도 vs 정확도** 곡선으로 분석. |
| **도메인별 정확도** | 정수론/기하/대수/조합 등으로 나눠 정확도 집계 → 약한 도메인 집중 개선. |
| **오류 분류 활용** | syntax/runtime/timeout/wrong_answer 등으로 분류해, **어떤 실패가 많은지** 보고 (코드 품질 vs 전략 선택 vs 검증 보강) 우선순위 정하기. |

### 4.3 중기: 고난이도·IMO 쪽으로 올리기

| 방향 | 내용 |
|------|------|
| **Theoretician 경로 강화** | N이 큰 수론·대수 문제에서 SymPy/수식 유도 비중 높이기, 프롬프트·예제 보강. |
| **기하 전용 강화** | GeometricSolver 사용 비율·성공률 측정, 실패 케이스 분석 후 sympy.geometry·좌표계 템플릿 확장. |
| **증명(proof) 경로** | proof 타입일 때 “코드만”이 아니라 단계별 주장·근거 구조를 유도하는 전용 프롬프트/후처리 실험. |
| **Self-Consistency / 앙상블** | 동일 문제에 여러 전략·시드로 풀고 일치하는 답 선택 (목표: 단일 전략 대비 정확도 +1~3%). |

### 4.4 장기: 평가·리포트 완전성 (L5)

- **도메인별 정확도**를 매 실행마다 자동 집계.  
- **정량적 난이도(DifficultyMetrics)** 를 문제별로 부여해, 난이도 구간별 곡선·그라디언트 트렌드 자동 리포트.  
- **수학 그라디언트 L5** 목표: “모든 메트릭 + 도메인별 분석 + rigor_report”까지 한 번에 나오게.
